=== Evaluate CMS options

Since this is one of the core features of the website, choosing the right CMS is going to be an essential decision. Most likely it will run in headless mode: the site will retrieve document information via a REST api and populate whatever custom components we define.

It'll also be used for the blog and the newsletter. While the blog is part of the site and will use the same rendering strategy as the other documents, the newsletter will probably use whatever the CMS supports, so I need to weigh its document rendering features.

Can the CMS push notifications to the backend when a new document is created, so the backend is aware? (listings, for example, blog posts etc.)
